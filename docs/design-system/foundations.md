# 기초 원칙

화면의 위계는 **작업 순서, 정렬, 간격, 짧은 설명**으로 만든다. 현재 랜덤 JSON 생성 화면처럼 기본 설정을 한눈에 읽게 하고, 상세 제어는 사용자가 필요할 때 접근하게 한다. 방향의 근거는 [문서 기준](index.md)에 있다.

## 정보 위계와 밀도

| 분류 | 원칙과 이유 | 적용과 확인 방법 |
| --- | --- | --- |
| 불변 | 가장 먼저 결정할 입력을 위에 둔다. 사용자가 결과의 형태를 정한 뒤 크기를 조절할 수 있어야 한다. | 기준 화면의 결과 구조 → 수량·깊이 → 출력 형식 순서를 확인한다. |
| 불변 | 기본 경로는 고급 설정을 열지 않아도 완료할 수 있다. | 기본값만으로 유효한 설정을 구성하고 실행할 수 있는지 확인한다. |
| 가변 | 정보량에 따라 편집 영역과 폼의 비중을 바꾼다. | 짧은 수치 입력은 행으로, 긴 스키마는 넓어지는 편집 영역으로 배치한다. |
| 조건부 | 결과를 바꾸는 선택의 설명은 그 선택이 활성화됐을 때 가까이에 보인다. | JSON5 선택 시 형식 설명이 나타나는 기존 동작을 따른다. |
| 금지 | 단순한 설정에 큰 제목, 장식 카드, 반복된 설명을 더해 핵심 입력을 밀어내지 않는다. | 입력을 찾기 위해 장식 영역을 먼저 지나야 한다면 정보 위계를 다시 검토한다. |

정렬은 관계를 표현한다. 이름·입력·범위는 같은 행에서 읽게 하고, 별도 목적의 설정은 구분선이나 그룹으로 분리한다. 정보량이 많은 화면에서도 모든 영역을 같은 크기의 상자로 만들 필요는 없다. [배치 근거: JetBrains Layout](https://plugins.jetbrains.com/docs/intellij/layout.html).

## 색상과 글꼴

**불변:** 본문, 보조 설명, 비활성, 오류, 주 동작의 역할을 구분한다. 역할별 실제 색상과 글꼴은 현재 호스트 UI를 따르며, 플러그인 전용 팔레트나 서체를 지정하지 않는다. 기준 화면은 일반 컨트롤의 글꼴을 직접 지정하지 않고, 범위·요약에는 플랫폼의 보조 설명 전경색을 사용한다.

**조건부:** 코드와 JSON을 읽는 편집 영역은 에디터의 글꼴·구문 표현을 따른다. 입력 라벨까지 코드용 고정폭 글꼴로 통일하지 않는다. 테마와 글꼴 설정이 바뀌어도 정보의 역할은 유지한다.

**금지:** 강조를 위해 임의의 HEX 색상이나 고정 글자 크기를 넣지 않는다. 오류를 색상 하나로만 표시하지 않는다. 실제 연결은 [토큰과 구현 값](tokens.md), 점검 기준은 [접근성](accessibility.md)이 소유한다.

## 간격과 크기

**불변:** 관련 입력끼리는 가까이 두고, 다른 판단으로 넘어가는 곳에 간격을 둔다. 기본 행 높이와 컨트롤 간격은 플랫폼 배치 체계를 사용한다. 소스에 명시된 본문 여백과 폭만 [수치 기준](tokens.md)에 기록한다.

**가변:** 창 높이는 표시 중인 내용에 따른다. 긴 편집 영역은 늘릴 수 있고, 접힌 고급 설정은 공간을 차지하지 않는다. 사용자가 늘린 창 크기를 일반적인 입력 변경 때마다 초기화하지 않는다.

**조건부:** 동일 다이얼로그 안에서도 탭별 필요한 크기가 다를 수 있다. 숨긴 탭 때문에 현재 탭이 불필요하게 커지지 않도록 한다. 상세 동작은 [작업 다이얼로그](components/task-dialog.md)가 소유한다.

## 형태, 깊이, 아이콘

기준 화면은 표준 필드·라디오 버튼·체크박스·콤보박스·구분선으로 구성한다. 모서리, 테두리 두께, 선택 배경, 그림자는 호스트 컨트롤이 결정한다. 별도의 카드 형태나 그림자 토큰은 확인되지 않았으므로 만들지 않는다.

다이얼로그 내부의 텍스트 라벨에 장식 아이콘을 추가하는 것은 기준 패턴이 아니다. 도구 창의 생성 진입점은 기존 `JsoninjaIcons.getGenerateIcon(project)` 선택 경로를 사용한다. 아이콘의 플랫폼 연결은 [플랫폼 적용](platforms/intellij-platform.md)에 있다.

## 움직임과 상태 전달

기준 화면에는 별도의 애니메이션 지속 시간 규칙이 없다. 상태 변화는 입력의 활성화, 설명의 표시, 요약의 갱신, 필요한 창 크기 조정으로 전달한다. 새로운 화면에서도 호버 시 컨트롤 크기를 바꾸거나 입력 초점을 이동시켜 읽기·입력을 방해하지 않는다.

비동기 작업은 사용자의 이후 편집을 덮어쓰지 않아야 한다. 실행 후 결과 적용에 대한 기존 경계는 [상호작용 패턴](patterns.md)에 연결한다.
