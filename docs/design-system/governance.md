# 운영과 검증 기록

사용자가 선택한 현행 랜덤 JSON 생성 화면을 기준으로, 관련 결정의 정본을 유지한다. 문서 기준은 요청받은 화면에 적용하며, 기존 UI를 일괄 개편하거나 새 공통 컴포넌트를 도입하는 근거로 확대하지 않는다.

## 방향과 변경 판단

2026-09-27에 사용자는 **현재 저장소의 하단 요약과 접이식 고급 옵션이 있는 다이얼로그**를 기준으로 확정했다. 별도의 색상·서체·브랜드 표현을 추가하는 결정은 없었다. 이 선택과 현행 구현에 근거해 기초 원칙, 수치, 컴포넌트, 상호작용을 연결했다.

이후 같은 날 사용자는 내용이 적으면 설정을 숨기지 않고, 내용이 많은 경우 일반 사용자에게 불필요한 고급 기능만 접도록 문서와 API 다이얼로그 수정을 요청했다. 이 명시적 요구가 [기본 노출과 고급 설정의 적용 조건](patterns.md#기본-노출과-고급-설정의-적용-조건)의 근거다. 생성 화면의 접이식 구성을 모든 다이얼로그에 적용하지 않는다.

| 변경 종류 | 처리 |
| --- | --- |
| 확정한 방향 안의 설명 보완·잘못된 참조 수정 | 해당 정본과 영향을 받는 연결을 수정한다. 방향을 다시 고르는 절차는 요구하지 않는다. |
| 특정 컴포넌트의 새로운 상태·변형 | 사용자 작업과 적용 조건을 밝히고 기존 표현으로 가능한지 확인한다. 실제 구현 근거와 검증 범위를 남긴다. |
| 기본/고급의 위계, 적용 목적지, 주 동작 의미 변경 | 단순한 외형 수정으로 처리하지 않고 사용자 요구를 확인한다. |
| 새 팔레트·서체·공통 크기 체계 | 기존 방향에 없는 결정으로 구분한다. 임의의 관례를 정본으로 올리지 않는다. |

동일 결정은 한 파일에서 소유한다. 수치를 바꾸면 [토큰](tokens.md), 입력 조건은 해당 [컴포넌트](components/index.md), 작업 흐름은 [패턴](patterns.md), 사용자 표현은 [문구](content.md)를 수정하고 관련 링크를 확인한다.

## 적용과 검토

신규 화면이나 요청받은 UI 수정에서 적용 가능한 규칙을 사용한다. 기존의 모든 다이얼로그가 이 기준에 맞는다고 선언하거나, 문서 생성만으로 일괄 이행을 요구하지 않는다.

검토에서는 사용자의 첫 판단, 상세 제어의 필요 시점, 상태 전환 후 남는 값, 실제 적용 대상, 오류를 고칠 위치를 확인한다. 코드의 지원 범위와 공개 API 경계는 [플랫폼 문서](platforms/intellij-platform.md)를 따른다.

문제의 원인은 다음처럼 구분한다.

- 규칙이 실제 작업을 설명하지 못하면 해당 문서의 판단을 수정한다.
- 규칙은 맞지만 소비자가 어기면 구현 문제로 기록한다.
- 실행한 검사가 그 상태를 다루지 않으면 확인 범위의 한계로 남긴다.
- 도구가 다른 버전이나 다른 화면을 보여주면 기준을 바꾸지 않고 검증 환경을 구분한다.

반복된 문제가 확인되면 당시 입력·상태·버전, 수용한 수정, 비교 가능한 재검증 결과를 이 파일에 기록한다. 한 번의 관찰을 전체 제품의 재발률이나 개선 효과로 확대하지 않는다. 별도 일정·승인자 조직·출시 절차는 정하지 않았다.

## 기본 노출 기준과 API 다이얼로그 수정

2026-09-27의 후속 요청에 따라 기존 디자인 시스템의 적용 조건을 보완했다. API 불러오기 화면은 내용이 적은데도 인증과 Content-Type을 고급 영역에 넣어, 요청 구성을 확인하는 데 펼침 조작을 요구했다. 원인은 접이식 패턴의 적용 조건이 불명확한 문서와 이를 과하게 적용한 화면 판단이며, 새로운 색상·크기 체계의 문제가 아니다.

문서의 판단은 [상호작용 패턴](patterns.md#기본-노출과-고급-설정의-적용-조건)에 두고 기초 원칙·고급 설정·작업 다이얼로그·플랫폼 연결을 맞췄다. 별도의 구현 작업으로 [API 뷰](../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/loadJson/LoadJsonFromApiDialogView.kt)에서 접이식 영역을 제거하고, [프레젠터](../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/loadJson/LoadJsonFromApiDialogPresenter.kt)의 오류 시 펼침 요청도 제거했다. 선택한 인증 필드로 오류를 연결하는 처리는 유지했다.

| 대표 상황 | 이번 확인 내용과 수준 |
| --- | --- |
| 내용이 적은 API 폼의 최초 상태 | 인증과 Content-Type이 조건 없이 구성되고 접이식 그룹이 없는 것을 소스로 확인 |
| 인증 없음 / Basic / Bearer | 인증 선택은 계속 노출하고, 해당 방식의 자격 증명만 조건부 표시하며 값을 초기화하지 않는 경로를 소스로 확인 |
| GET / POST·PUT·DELETE | 본문 표시 여부와 관계없이 인증·Content-Type 행이 본문 앞에 유지되는 배치를 소스로 확인 |
| 여러 세부 행이 있는 생성 폼 | 시드 제어의 기존 접이식 계약을 유지. 위에 기록한 테스트 결과는 이전 문서화의 근거이며 이번에 재실행하지 않음 |

작업 디렉터리 `/Users/buyong/workspace/private/json-helper2`에서 `./gradlew compileKotlin`을 실행해 **BUILD SUCCESSFUL**, `compileKotlin` 실행을 확인했다. 이 결과는 변경된 코드의 컴파일 확인이며, 실제 창 렌더링·클릭·키보드 동작을 검증한 것은 아니다. 이번 수정은 기본 노출 판단과 API 화면에 한정하며 전체 디자인 시스템의 시각·접근성 검증 완료로 해석하지 않는다.

## 문서 검증

문서 집합의 구조는 다음 명령으로 확인한다. 구조 검사는 파일 책임과 링크를 확인하는 검사이며, 시각 품질·방향 승인·접근성 통과를 대신하지 않는다.

```bash
python3 /Users/buyong/.codex/skills/document-writing/scripts/validate_design_system_output.py docs/design-system --prebuilt default --platform intellij-platform
```

실행 결과: 문서 루트, `index.md`, 인덱스 대체 여부, `platforms/intellij-platform.md`의 구조 검사 **4개 통과**. 별도 읽기 전용 검사에서 Markdown 파일 **13개**, 내부 링크 **109개**를 확인했고, 누락 파일·잘못된 소스 행 참조·닫히지 않은 코드 블록·행 끝 공백은 발견하지 못했다.

세부 수치·문구·동작은 연결한 소스와 대조한다. 외부 지침은 [플랫폼 문서의 공식 자료](platforms/intellij-platform.md)에 연결했다. `ui-ux-pro-max`의 검색은 레이블·초점·키보드·오류 전달의 점검에 참고하고, 구현 연결은 JetBrains 공식 자료와 현재 코드에 근거했다.

## 미확인 범위와 남은 결정

현재 저장소 버전의 실제 다이얼로그 렌더링, 밝은/어두운/고대비 테마, UI 확대, 긴 번역, 전체 키보드 이동과 화면 읽기 프로그램은 확인하지 않았다. `runIde`, Plugin Verifier, 동적 재설치·제거, 최종 생성 결과의 에디터 반영도 이번 문서 작업에서는 실행하지 않았다.

실행 중인 IDE에서 관찰한 다이얼로그는 제목과 그룹 구성이 현재 저장소와 달랐다. 해당 화면은 취소하고, 관찰을 위해 열었던 도구 창을 다시 숨겼다. 이 화면의 외형을 현재 구현의 검증 결과로 사용하지 않았다.

현재 문서 범위에서 남은 방향 선택은 없다. 중앙 토큰 모듈, 추가 플랫폼, 다른 복합 화면의 전용 컴포넌트는 결정하거나 구현하지 않았다. 이후 필요해지면 해당 요청과 근거에 맞춰 범위를 확장한다.
