# 접근성

접근성은 공통 UI 기준의 일부다. **표준 컴포넌트를 사용했다는 사실만으로 접근성 통과를 선언하지 않는다.** 아래 항목은 설계·구현 시 유지할 기준이며, 이번에 실제 확인한 범위는 [검증 기록](governance.md)에서 구분한다.

## 키보드와 초점

입력·선택·펼침·보조 동작·실행·취소에 키보드로 접근할 수 있어야 한다. 이동 순서는 읽는 순서와 일치하고, 초점 표시를 장식 때문에 제거하지 않는다. 입력 변경이나 요약 갱신만으로 다른 필드에 초점을 옮기지 않는다.

새 내용이 표시되면 키보드로 도달할 수 있어야 하며, 접힌 영역 안의 보이지 않는 컨트롤에 머무르게 하지 않는다. 플랫폼의 기본 탐색과 컨트롤별 키 동작을 보존한다. [JetBrains 접근성 지침](https://plugins.jetbrains.com/docs/intellij/accessibility.html).

기준 화면의 초기 초점은 객체 모드에서는 속성 수, 배열 모드에서는 객체 수다. 이는 [뷰의 초점 선택](../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/generateJson/random/GenerateRandomJsonTabView.kt#L100)과 다이얼로그의 위임을 소스로 확인한 내용이다. 전체 키보드 이동을 직접 검증한 결과는 아니다.

## 이름, 상태, 오류 전달

입력의 목적은 항상 보이는 라벨로 제공한다. 자리표시자를 유일한 이름으로 쓰지 않는다. 보조 기술에도 이름·역할·선택 여부·활성 여부·펼침 상태가 전달되는지 확인한다. 라벨, 설명, 내부 테스트용 `name` 속성은 서로 다른 역할이다.

오류는 색상 외에 텍스트와 수정 위치를 제공한다. 필드에 연결한 검증과 숨은 오류의 공개는 기준 화면에서 유지할 동작이다. 화면 읽기 프로그램이 하단 요약의 동적 갱신을 자동으로 알린다고 가정하지 않는다. 실제 전달은 별도 확인 항목이다.

## 테마, 대비, 확대

본문·설명·범위·오류·초점 표시가 밝은 테마와 어두운 테마에서 구별되어야 한다. 보조 설명의 낮은 위계가 읽기 어려운 저대비를 허용하는 것은 아니다. 임의 색상으로 보정하기 전에 플랫폼 연결과 실제 대비를 확인한다.

배율과 UI 글꼴을 키웠을 때 필드·범위·시드 버튼·하단 요약이 겹치거나 잘리지 않는지 확인한다. [확인된 치수](tokens.md)는 컨트롤의 내용 요구를 무시하는 고정 크기가 아니다. 축소·확대와 번역 때문에 생긴 문제를 글자를 더 작게 만드는 방식으로 해결하지 않는다.

별도의 필수 모션은 없다. 정보는 움직임을 보지 않아도 확인할 수 있어야 하며, 새 애니메이션을 디자인 시스템의 기본값으로 도입하지 않는다.

## 검증할 대표 조건

| 조건 | 관찰할 결과 | 이번 확인 수준 |
| --- | --- | --- |
| 고급 설정 접힘 → 펼침 | 숨긴 필드의 가시성, 내용에 따른 선호 높이 변경 | 기존 컴포넌트 테스트 통과 |
| 시드 유지 꺼짐 → 켜짐 | 관련 입력만 활성화 | 기존 컴포넌트 테스트 통과 |
| 잘못된 시드 입력 | 해당 필드에 오류 연결, 수정할 필드가 보임 | 기존 프레젠터 테스트 통과. 접힌 상태에서 자동으로 펼치는 전환은 소스 확인에 한정 |
| 전체 키보드 순환 | 모든 기능 접근, 초점 가시성, 탈출 가능 | 미실행 |
| 화면 읽기 프로그램 | 이름·상태·오류·동적 요약 전달 | 미실행 |
| 밝은/어두운/고대비 테마 | 상태 구분과 실제 대비 | 미실행 |
| UI 확대와 긴 번역 | 겹침·잘림 없이 입력 및 실행 가능 | 미실행 |

검증 도중 문제가 발견되면 공통 규칙의 결함인지, 특정 구현이 규칙을 지키지 못한 것인지 구분한다. 접근성을 맞추기 위해 승인된 정보 위계 자체를 버리거나, 한 환경의 실패를 모든 화면의 새 치수 규칙으로 일반화하지 않는다.
