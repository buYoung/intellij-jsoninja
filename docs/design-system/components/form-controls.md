# 폼 컨트롤

이름·입력·제약을 가까이 배치해 사용자가 설정의 뜻과 허용 범위를 함께 읽도록 한다. 기준 구현은 [GenerateRandomJsonTabView](../../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/generateJson/random/GenerateRandomJsonTabView.kt)와 [GenerateRandomJsonTabPresenter](../../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/generateJson/random/GenerateRandomJsonTabPresenter.kt)다.

## 구성과 변형

| 목적 | 기준 컨트롤 | 배치와 의미 |
| --- | --- | --- |
| 서로 배타적인 짧은 선택 | `buttonsGroup` 안의 라디오 버튼 | 객체 / 객체 배열을 한 행에서 비교 |
| 범위가 정해진 수량 | `intTextField`와 범위 라벨 | 이름 → 입력 → 허용 범위 순서 |
| 출력 형식 선택 | `ComboBox` | JSON / JSON5 선택과 관련 설명 연결 |
| 독립된 사용 여부 | 체크박스 | 시드 유지처럼 켜짐/꺼짐을 표현 |
| 재현 가능한 정수 식별값 | 텍스트 필드와 검증 | 긴 시드를 입력하며 인접 버튼으로 교체 가능 |
| 보충 설명 | `comment(...)` | 현재 선택의 조건과 결과를 설명 |

짧은 이진 선택을 불필요하게 드롭다운 안에 숨기거나, 여러 독립 체크박스로 배타적 선택을 만들지 않는다. 기존 숫자 범위는 업무 규칙이므로 디자인 토큰과 분리한다.

## 확인한 범위와 기본값

초기값은 [JsonGenerationConfig](../../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/generateJson/model/JsonGenerationConfig.kt) 기준이다. 이전에 성공한 생성 설정이 있으면 세션 서비스가 그 설정을 제공한다.

| 입력 | 유효 범위 | 새 세션의 기본값 | 상태 조건 |
| --- | --- | --- | --- |
| 결과 구조 | 객체 / 객체 배열 | 객체 | 하나만 선택 |
| 객체 수 | `1..100` | 배열용 값 `5` | 객체 모드에서는 `1` 표시·비활성 |
| 객체당 속성 수 | `1..100` | 객체 모드 `5`, 배열 모드 `3` | 모드별 입력값을 따로 기억 |
| 최대 중첩 깊이 | `1..10` | `3` | 두 모드에서 사용 |
| 출력 형식 | JSON / JSON5 | JSON | JSON5일 때 설명 표시 |
| 시드 | `Long` 범위의 정수 | 고정 숫자 없음 | 시드 유지가 켜진 경우에 검증 |

수량 필드의 `keyboardStep`은 `1`이다. 시드의 초기 숫자는 생성되거나 이전 설정에서 오므로 문서 예시의 특정 숫자를 기본값으로 고정하지 않는다.

## 크기와 토큰 연결

일반 입력의 높이, 글꼴, 테두리, 초점 표현은 표준 컨트롤을 따른다. 라벨과 입력의 기본 정렬은 UI DSL 행이 담당한다. 범위 라벨의 색상, 시드의 문자 열 수, 본문 여백은 [토큰과 구현 값](../tokens.md)에 연결한다.

## 상태와 검증

**불변:** 현재 작업에서 사용하는 값만 검증하고, 오류는 해당 입력에 연결한다. 객체 모드에서 저장만 해 둔 배열용 수량을 검증해 생성을 막지 않는다.

**조건부:** 구조 선택을 바꾸면 현재 모드의 입력을 기억한 뒤 새 모드의 값을 표시한다. 이 전환 중 생긴 중간 문서 이벤트를 그대로 최종 설정 변경으로 전달하지 않도록 뷰가 처리한다. 관찰할 결과는 모드를 왕복해도 각각의 입력값이 남는 것이다.

**조건부:** JSON5 설명은 선택에 따라 나타난다. 시드 입력과 인접 버튼은 [고급 설정 계약](advanced-options.md)에 따라 함께 활성화된다.

프레젠터는 허용 범위를 다시 검사하고 `ValidationInfo`에 실제 필드를 연결한다. 요약을 만들 때 잘못된 숫자를 정상 기본값처럼 표시하지 않는다.

## 조합, 문구, 적응

숫자의 의미와 범위는 같은 행에서 읽게 한다. 긴 설명은 독립된 보조 설명으로 둔다. 라벨을 줄이느라 의미를 없애거나, 공간을 맞추기 위해 오류 메시지의 범위를 생략하지 않는다. 문구는 [문구와 용어](../content.md)를 따른다.

라벨 길이가 크게 다르거나 긴 편집 영역이 필요한 경우에는 같은 행 정렬을 기계적으로 강제하지 않는다. JSON Schema 탭의 상단 검색 라벨과 확장 가능한 편집 영역이 기존의 다른 배치 사례다.

## 접근성과 사용 제한

라벨과 입력의 연결, 키보드 이동, 비활성 상태의 의미가 유지돼야 한다. 세부 기준은 [접근성](../accessibility.md)에 있다. 내부 컴포넌트 `name`을 화면 읽기 프로그램용 이름으로 간주하지 않는다.

원시 텍스트 필드만 두고 오류를 상단 메시지로 몰거나, 잘못된 입력을 조용히 범위 안으로 바꾸는 방식은 피한다. 사용자는 자신이 입력한 값과 적용될 값을 확인할 수 있어야 한다. 별도의 호버 크기 변화나 입력 애니메이션은 기준에 없다.
