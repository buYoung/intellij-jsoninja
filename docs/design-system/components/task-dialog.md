# 작업 다이얼로그

짧은 설정 작업을 마친 뒤 명시적으로 실행하는 화면이다. 기준 구현은 [GenerateJsonDialog](../../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/generateJson/GenerateJsonDialog.kt)와 [GenerateJsonDialogView](../../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/generateJson/GenerateJsonDialogView.kt)다.

## 구성

| 위치 | 구성 요소 | 책임 |
| --- | --- | --- |
| 창 제목 | JSON 생성 | 수행할 작업의 이름 |
| 상단 | 무작위 / JSON Schema 탭 | 입력 방식 전환 |
| 본문 앞부분 | 결과 구조, 객체 수, 객체당 속성 수, 최대 중첩 깊이 | 기본 생성 설정 |
| 본문 중간 | 구분선, 출력 형식, 조건부 설명 | 결과 형식 선택 |
| 본문 뒷부분 | 접이식 고급 설정 | 선택적인 시드 제어 |
| 공통 하단 | 구분선, 결과 요약, 적용 대상 설명 | 실행 결과와 영향 확인 |
| 플랫폼 액션 영역 | 생성, 취소 | 확정과 닫기 |

위 표는 생성 다이얼로그의 구성이다. 상단부터 입력을 읽고 하단에서 실행 영향을 확인하는 관계를 유지하되, 다른 화면의 탭과 접이식 영역은 [적용 조건](../patterns.md#기본-노출과-고급-설정의-적용-조건)에 맞게 선택한다. 실제 버튼 순서와 외형은 [IntelliJ Platform 적용](../platforms/intellij-platform.md)을 따른다.

## 변형과 크기

**가변:** 짧은 폼은 필요한 높이만 사용한다. 스키마처럼 긴 입력이 중심이면 본문의 편집 영역이 늘어난다. 공통 하단의 목적은 동일하다.

[API 불러오기 뷰](../../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/loadJson/LoadJsonFromApiDialogView.kt)는 접이식 영역을 두지 않는 짧은 폼의 변형이다. 요청 방식·URL 아래에 인증과 Content-Type을 항상 표시하며, 고정된 `application/json`은 입력 필드 대신 값으로 보여준다. Basic을 선택하면 사용자 이름·비밀번호, Bearer를 선택하면 토큰 필드를 표시하고, 본문 편집기는 POST·PUT·DELETE에서 표시한다. 본문이 나타나도 인증과 Content-Type은 그 위에 유지한다.

API 화면의 하단은 요청 요약과 새 탭 안내이며, 표준 액션 영역에 불러오기·닫기를 둔다. 자격 증명과 본문이 표시될 때 현재 폭을 유지하며 높이를 조정하고, URL을 입력하는 동안에는 창 크기를 다시 맞추지 않는다. 이 동작은 [API 다이얼로그](../../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/loadJson/LoadJsonFromApiDialog.kt)가 맡는다.

**조건부:** 탭 영역의 선호 폭·최소 폭 하한과 본문 여백은 [수치 기준](../tokens.md)을 따른다. 이 값은 창 테두리까지 포함한 전체 폭이 아니다. 최종 최소 크기는 루트 패널의 요구 크기와 창 인셋으로 계산한다.

## 상태와 동작

아래 표는 생성 다이얼로그의 상태 전환이다. API 화면의 구성과 조건부 표시는 위의 변형 설명을 따른다.

| 전환 | 현재 동작 |
| --- | --- |
| 처음 열기 | 무작위 탭과 초기 설정을 구성하고 요약을 갱신한다. |
| 일반 입력 변경 | 요약과 필요한 최소 크기를 갱신하되 기존 창 크기를 기본적으로 유지한다. |
| 고급 설정 펼침/접힘 | 현재 폭을 유지하며 선호 높이에 맞춘다. 최소 크기를 밑돌 수는 없다. |
| 탭 변경 | 떠나는 탭의 창 크기를 기억하고, 돌아온 탭의 기록 또는 선호 크기를 적용한다. |
| 숨긴 탭 | 그 탭의 선호·최소 크기가 현재 탭의 크기를 늘리지 않도록 한다. |
| 입력 오류 | 활성 탭의 검증 결과를 다이얼로그에 연결한다. |
| 취소 | 생성 액션의 결과 생성·적용 경로로 들어가지 않는다. |

탭 크기 기록은 `GenerateJsonDialog` 인스턴스 안의 상태다. IDE 재시작이나 모든 재열기에 걸친 저장 계약으로 설명하지 않는다.

## 조합과 구현 연결

`GenerateJsonDialogPresenter`가 각 탭의 옵션 변경을 받아 요약과 레이아웃을 갱신한다. 뷰끼리 직접 서로의 컨트롤을 조작하는 범용 계약은 없다. 다른 화면에서 같은 구성을 사용할 때는 기존 역할 분리를 참고하되, 생성 전용 프레젠터를 범용 폼 API로 취급하지 않는다.

기준 호출은 [GenerateRandomJsonAction](../../../src/main/kotlin/com/livteam/jsoninja/actions/GenerateRandomJsonAction.kt#L39)에 있다. `GenerateJsonDialog(project)`를 만들고 `showAndGet()`이 참일 때 `getConfig()`로 설정을 읽는다. 이후 생성과 최종 적용은 다이얼로그 밖의 액션·서비스가 맡는다.

## 문구와 접근성

제목·주 동작·목적지 문구는 [문구 정본](../content.md), 초기 초점과 키보드 검증은 [접근성](../accessibility.md)을 따른다. 입력 오류 때문에 실행할 수 없는 상황에서는 오류의 위치와 이유를 확인할 수 있어야 한다.

## 사용과 금지

입력 설정과 실행 판단이 중심인 작업에 사용한다. 지속적으로 열어 두는 편집 작업에는 별도 작업 영역이 적합할 수 있다.

모든 탭을 가장 큰 탭의 높이에 맞추거나, 숫자 하나를 바꿀 때마다 창을 초기 크기로 줄이지 않는다. 전자는 단순 작업에 불필요한 빈 공간을 만들고 후자는 사용자의 크기 조정을 무효화한다. 현재 구현의 탭별 크기 기억과 상태별 높이 조정을 기준으로 삼는다.

별도의 전환 애니메이션 수치는 정하지 않는다. 대표 테스트는 고급 영역의 컴포넌트 선호 크기를 확인했으며, 운영체제 창의 실제 크기 변경까지 검증하지는 않았다.
