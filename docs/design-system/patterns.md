# 상호작용 패턴

반복해서 사용할 핵심 흐름은 **설정 → 결과 확인 → 실행**이다. 기본 경로를 짧게 유지하면서 고급 제어와 오류 복구를 같은 화면에서 제공한다.

## 기본 입력에서 실행까지

| 순서 | 사용자의 판단 | 배치와 이유 | 허용되는 변화 |
| --- | --- | --- | --- |
| 1 | 어떤 방식으로 만들 것인가 | 방식이 다른 경우 상단 탭으로 구분 | 방식이 하나면 탭이 필요하지 않음 |
| 2 | 어떤 결과를 만들 것인가 | 결과 구조를 수량보다 먼저 표시 | 작업에 따라 언어·입력 원본 등이 첫 선택일 수 있음 |
| 3 | 얼마나, 어떤 형식으로 만들 것인가 | 관련 수치와 범위를 같은 행에 두고 출력 형식을 이어 배치 | 긴 본문이 중심인 경우 편집 영역 아래에 출력 옵션 배치 |
| 4 | 세부 제어가 필요한가 | 아래 적용 조건을 만족하는 고급 기능만 접음 | 내용이 적으면 그대로 노출하며, 접는 경우에도 활성 설정이나 오류에 따라 펼칠 수 있음 |
| 5 | 무엇이 어디에 적용되는가 | 하단에 결과 요약과 목적지를 유지 | 요약 내용은 모드에 맞게 변경 |
| 6 | 실행할 것인가 | 다이얼로그의 주 동작을 구체적인 동사로 표시 | 버튼 순서는 [플랫폼 규칙](platforms/intellij-platform.md)에 위임 |

이 흐름은 생성 화면의 기존 구성을 재사용한 것이다. 모든 작업을 마법사 단계나 별도 화면으로 나누라는 의미가 아니다. 전체 구조는 [작업 다이얼로그](components/task-dialog.md)가 소유한다.

## 기본 노출과 고급 설정의 적용 조건

**불변:** 내용이 많지 않은 다이얼로그는 설정을 기본 화면에 보여준다. 몇 가지 입력과 설명만으로 작업을 이해할 수 있다면, 사용자가 설정을 찾기 위해 고급 영역을 펼치게 하지 않는다.

**조건부:** 다음 두 조건을 모두 만족하는 경우에만 접이식 고급 설정을 사용한다.

1. 입력·옵션·설명이 많아 기본 작업에 필요한 정보를 찾거나 읽기 어렵다.
2. 접을 기능은 일반 사용자의 기본 작업에 필요하지 않은 전문적인 세부 제어다.

내용이 많아도 요청 구성, 적용 대상, 실행 판단에 필요한 정보는 기본 화면에 남긴다. 고급 기능이 없는 화면은 정렬·그룹·간격과 편집 영역 크기로 정보량을 다룬다. 항목 수나 창 높이의 일률적인 임계값은 정하지 않는다.

**금지:** 선택 사항, 사용 빈도가 낮을 것이라는 추정, 기본값 또는 고정값이라는 이유만으로 고급 기능으로 분류하지 않는다. 기준 화면에 접이식 영역이 있다는 사실도 다른 화면의 설정을 숨기는 근거가 아니다.

| 상황 | 적용 | 이유 |
| --- | --- | --- |
| API 불러오기처럼 요청 방식·URL·인증·Content-Type으로 구성한 짧은 폼 | 인증과 Content-Type을 항상 노출 | 현재 요청 구성을 바로 확인하는 정보이며, 별도 펼침 조작이 필요할 만큼 내용이 많지 않음 |
| 기본 생성 설정에 시드 입력·재현 설명 등 여러 세부 행이 더해지는 무작위 생성 폼 | 시드 제어를 고급 설정으로 접음 | 일반적인 JSON 생성에는 필요하지 않은 재현 제어를 기본 입력과 분리 |
| 현재 선택에 해당하지 않는 종속 입력 | 아래의 조건부 표시 규칙 적용 | 예를 들어 인증 없음에서는 자격 증명 입력이 필요하지 않지만 인증 방식 자체는 계속 보여야 함 |

**검증:** 짧은 폼에서 주요 설정을 펼침 조작 없이 확인할 수 있는지, 내용이 많은 폼에서 접힌 기능 없이 일반 작업을 완료할 수 있는지 확인한다. 접은 기능이 활성화돼 있으면 상태를 요약에 남기고, 관련 오류가 생기면 수정할 입력을 드러낸다. 펼침·값 보존의 상세 계약은 [고급 설정](components/advanced-options.md)에 있다.

## 숨김과 비활성의 구분

**조건부:** 지금 사용할 수 없지만 선택 관계를 이해하는 데 필요한 입력은 비활성으로 남긴다. 객체 모드의 객체 수는 `1`을 표시하며 비활성화된다. 배열 모드로 돌아가면 앞서 입력한 배열용 값을 복원한다.

반면 JSON5 설명은 JSON 출력일 때 숨긴다. 현재 선택에 없는 형식 설명을 계속 보여주지 않는다. API 불러오기에서도 선택한 인증 방식의 자격 증명 필드와 본문을 지원하는 요청 방식의 편집기만 표시한다. 이는 현재 선택에 따라 필요한 입력을 보여주는 동작이며, 설정을 고급 영역으로 접는 판단과 구분한다.

**금지:** 비활성 입력의 오류가 현재 작업을 막게 하지 않는다. 값을 일시적으로 숨기거나 비활성화할 때 사용자가 입력한 별도 모드의 값을 덮어쓰지 않는다. 근거는 [무작위 뷰](../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/generateJson/random/GenerateRandomJsonTabView.kt#L231)와 [검증 분기](../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/generateJson/random/GenerateRandomJsonTabPresenter.kt#L51)다.

## 빠른 요약과 상세 입력의 연결

하단 요약은 현재 유효한 설정의 결과 구조·수량·형식을 짧게 알려준다. 정확한 제약과 수정은 위쪽 입력에서 다룬다. 요약이 입력을 대체하거나 실제 생성 미리보기인 것처럼 보이면 안 된다.

유효하지 않은 입력이 있으면 기존의 정상 요약 대신 설정 수정을 요청한다. 시드 유지가 켜지면 요약에 그 상태를 덧붙인다. 문구의 정본은 [문구와 용어](content.md), 갱신 흐름은 [결과 요약](components/result-summary.md)에 있다.

## 오류를 고칠 수 있는 상태로 안내

수치와 시드는 해당 입력에서 검증한다. 오류 메시지는 허용 범위를 알려주고, `ValidationInfo`를 필드에 연결한다. 잘못된 시드가 접힌 영역 안에 있으면 다이얼로그 검증 시 고급 설정을 펼쳐 수정 위치를 드러낸다.

시드 유지가 꺼져 있으면 입력한 시드를 사용하지 않으므로 그 입력의 오류도 막는 조건이 아니다. 펼침은 설명의 배치 상태이고, 시드 유지 선택은 기능의 활성 상태다. 두 상태를 혼동하지 않는다.

이 패턴은 오류 근처에서 수정하게 하는 [플랫폼 검증 지침](https://plugins.jetbrains.com/docs/intellij/validation-errors.html)과 현재 프레젠터의 분기에 근거한다.

## 실행 결과의 적용 대상 보존

현재 생성 액션은 사용자가 확인 버튼을 누른 뒤 대상 에디터·문서·수정 상태를 확보하고, 백그라운드에서 결과를 만든다. 적용 시 대상이 남아 있고 이후 문서 수정이나 더 최신 생성 요청이 없는지 확인한다. 탭 선택이 바뀌었다는 이유만으로 다른 탭에 결과를 쓰지 않는다.

근거: [생성 액션](../../src/main/kotlin/com/livteam/jsoninja/actions/GenerateRandomJsonAction.kt#L39) → [대상 확보와 최종 적용](../../src/main/kotlin/com/livteam/jsoninja/ui/component/main/JsoninjaPanelPresenter.kt#L97). 이 문서의 테스트 2개는 최종 에디터 반영을 실행 검증한 것은 아니다.

**조건부:** 시드와 설정은 랜덤 결과가 실제 적용된 뒤 프로젝트 세션에 기억된다. 취소·실패·오래된 결과 폐기는 새 성공 상태를 만들지 않는다. 현재 구현은 IDE 재시작 후 저장이나 기기 간 동기화를 보장하지 않는다. [세션 서비스](../../src/main/kotlin/com/livteam/jsoninja/services/random/RandomJsonGenerationSessionService.kt).

## 정보량이 많은 변형

JSON Schema 탭은 같은 다이얼로그 틀 안에서 원본 검색·편집 영역을 먼저 둔다. 편집 영역은 늘어나고, 출력 옵션과 공통 요약이 뒤따른다. 짧은 폼과 같은 정보 위계를 유지하면서 내용에 필요한 공간을 허용하는 사례다.

선택 속성을 주석으로 포함하는 모드에서는 JSON5를 선택하고 형식 변경을 비활성화하며 이유를 설명한다. 해당 모드를 해제하면 앞서 선택한 출력 형식을 복원한다. 이 사례는 모든 비활성 상태에 적용할 신규 기능이 아니라 [기존 스키마 뷰](../../src/main/kotlin/com/livteam/jsoninja/ui/dialog/generateJson/schema/GenerateSchemaJsonTabView.kt#L310)에서 확인한 종속 선택 처리다.
